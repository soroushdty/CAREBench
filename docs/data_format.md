# Data Format

CAREBench's built-in `paired_context` adapter (`adapters/paired_context/`) reads datasets in the **paired-context data format** described here. To use another layout, write a new adapter (see [`adapters.md`](adapters.md)).

A runnable, fully synthetic example lives in [`examples/synthetic/`](../examples/synthetic/). It is generated by `scripts/make_synthetic_dataset.py`.

## Study design the format encodes

Human reference observers (for example, physicians) label short EHR items (task instances) for each patient (context entity) twice:

1. **Context-free condition**: the item alone, with no patient information.
2. **Correct-context condition**: the same item with that patient's clinical snapshot.

Observers work in fixed groups (two per patient by default). Their labels are averaged within each group to give a consensus per (patient, item, category). The difference between the two conditions is the reference judgment shift (`delta_reference`) that model behaviour is compared against.

## Files

| File | Config key (Track 3 `data:` / Track 1) | Required |
|------|------------------------------------------|----------|
| `dataset.xlsx` | `dataset_path` / `DIR_DATASET` | yes |
| `patient_summaries.json` | `patient_summaries_path` / `DIR_CONTEXT` | yes for Track 3; Track 1 Stage 2 only |
| `mapping.json` | — / `DIR_JSON_MAP` | Track 1 preprocessing only |

### `dataset.xlsx`

Three sheets with the same columns:

| Sheet (default name) | Config key | Meaning |
|----------------------|------------|---------|
| `train` | `train_sheet` | Context-free labels for items used to train representation models |
| `test` | `test_sheet` | Context-free labels for the evaluation items |
| `interview` | `interview_sheet` | Correct-context labels for the same evaluation items |

Columns:

| Column (default name) | Config key | Type | Meaning |
|-----------------------|------------|------|---------|
| `Patient` | `patient_col` | int or str | Context entity ID; must match a key in `patient_summaries.json` |
| `Physician` | `physician_col` | int or str | Reference observer ID |
| `Item` | `item_col` | str | Item text shown to observers and models |
| one column per category | `classes` | 0/1 | Observer's label for that category |

Rules checked by the adapter:

- Every (patient, observer, item) triplet in the `test` sheet must also be in the `interview` sheet, and vice versa.
- Each (patient, item) in the reference sheets should have exactly `physician_count` observer rows (default 2). With `mismatch_error: true`, a mismatch stops the run; otherwise the rows are reported and skipped.

### `patient_summaries.json`

An object keyed by patient ID (as a string). Each value holds the clinical snapshot shown in the correct-context condition:

```json
{
  "1": {
    "summary": "46-year-old woman with ...",
    "medical_history": ["..."],
    "allergies": ["..."],
    "medication_history": ["..."],
    "social_history": ["..."],
    "labs": ["..."],
    "radiology": ["..."],
    "procedures": ["..."]
  }
}
```

Fields are rendered in the order above. A value may be a string or a list of strings, and missing fields render empty. Unless `skip_label_leakage_check: true` is set, the reasoning track refuses to run if an item's text appears verbatim in its own patient's snapshot.

### `mapping.json`

Maps a canonical item string to the raw variants that appear in the workbook, so that Track 1 preprocessing can merge spelling variants:

```json
{ "lisinopril 10 mg tablet": ["Lisinopril 10 mg tablet", "Lisinopril 10mg tab"] }
```

## Label space

The default categories are the ten sensitive-data categories used in the SHARES project (see [`shared/label_space.py`](../shared/label_space.py)). Any other set of category columns works: list them in `classes`, and give the definitions the Track 3 prompt should show in `class_definitions` (see [`adapters.md`](adapters.md#label-space-sharedlabel_spacepy)).

## Pointing a run at your data

Copy `configs/assay_config.yaml` (Track 3) or `configs/main_config.yaml` (Track 1) and change the paths, plus the column and sheet names if yours differ. Keep real patient data out of version control. `data/` and `output/` are git-ignored, so either is a safe local location.
